1Python for GenAI

Most GenAI work is Python “glue”: call a model API, clean text, store vectors, check the output, and serve the result through an API or UI.

What you must be comfortable with

  • Lists, dicts, functions, classes, list comprehensions, try/except, reading files, JSON (json.loads / json.dumps).
  • venv + pip, a requirements.txt, and keeping API keys in environment variables or a .env file that is in .gitignore.
  • requests/httpx for HTTP, asyncio for many calls at once, Pydantic to validate data, numpy for vectors, pandas for tables.
  • Serving: FastAPI (APIs), Streamlit or Gradio (quick demo UIs). Notebooks: Google Colab (free GPU).
  • HTTP status codes: 200 ok, 400 bad request, 401 bad key, 429 rate limit, 500/503 server problem.

Your first LLM call (two common SDK styles)

# pip install openai anthropic
import os
from openai import OpenAI
client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])     # never hard-code keys
r = client.chat.completions.create(
    model=MODEL,                                          # e.g. a current model name from the docs
    messages=[{"role": "system", "content": "You are concise."},
              {"role": "user", "content": "Explain RAG in one line."}],
    temperature=0.2)
print(r.choices[0].message.content)

import anthropic
client = anthropic.Anthropic()                            # reads ANTHROPIC_API_KEY
msg = client.messages.create(model=MODEL, max_tokens=300,
        system="You are concise.",                        # system prompt is its own field here
        messages=[{"role": "user", "content": "Explain RAG in one line."}])
print(msg.content[0].text)

Every chat API has the same idea: a list of messages with roles (system, user, assistant), a model name, and settings such as temperature and max tokens. Learn one SDK well; the others will feel familiar.

Say it in the interview“In production I keep keys in a secret manager, set timeouts, retry 429 and 5xx errors with exponential backoff, validate the model’s output with Pydantic, and log tokens, latency and cost for every call.”
Trap: committing a key to GitHub. Bots scan public repos within minutes. If it happens, revoke the key first, then clean history.

2ML & deep learning basics

Machine learning means learning patterns from examples instead of writing rules by hand. A model is a function with adjustable numbers (weights); training nudges those numbers until the model’s mistakes get small.

AI ⊃ Machine learning ⊃ Deep learning ⊃ Generative AI. Discriminative models decide (spam or not). Generative models create new text, images, audio or code.

Learning typePlain meaningExample
SupervisedExamples come with the right answer (label)Email → spam / not spam
UnsupervisedNo labels; find structureGroup customers into segments
Self-supervisedLabels come from the data itselfHide the next word, predict it — how LLMs pre-train
ReinforcementLearn by trial and rewardGame playing; RLHF for chatbots

Training in five words: predict, measure, adjust, repeat

  • Loss = how wrong the model is. Classification uses cross-entropy; regression uses mean squared error.
  • Gradient descent = walk downhill on the loss. Learning rate = size of each step (too big jumps around, too small is slow). Backpropagation computes which way is downhill for every weight.
  • Epoch = one pass over the training data. Batch = how many examples per update.
  • Neural network = layers of weighted sums followed by an activation (ReLU, GELU) that adds non-linearity. Softmax turns raw scores into probabilities that add up to 1.

Overfitting vs underfitting

Overfitting: the student memorised last year’s paper and fails a new one — great on training data, poor on unseen data. Fix with more data, regularisation, dropout, early stopping, a simpler model. Underfitting: too simple to learn even the training data. Always split data into train / validation / test.

Metrics you must explain with an example

MetricQuestion it answers
AccuracyWhat fraction did I get right? (misleading when classes are imbalanced)
PrecisionOf everything I flagged, how much was really positive? (cost of false alarms)
RecallOf all the real positives, how many did I catch? (cost of misses — e.g. disease screening)
F1Balance of precision and recall (harmonic mean)
Say it in the interview“LLMs are trained with self-supervised next-token prediction, so the same ideas apply: a loss (cross-entropy), gradient descent with backprop, and the risk of overfitting when we fine-tune on a small dataset.”

3Tokens & embeddings

Models don’t read words; they read tokens (pieces of words) and turn each into a list of numbers called an embedding. Similar meanings end up as nearby lists of numbers.

Tokens

  • Rule of thumb for English: 1 token ≈ 4 characters ≈ ¾ of a word, so 1,000 tokens ≈ 750 words. Tamil, Hindi and code often use more tokens per word.
  • Why it matters: price, speed and the context window are all counted in tokens.
  • Tokenizers: BPE (byte-pair encoding — start from characters and keep merging the most frequent pair; GPT family), WordPiece (BERT), SentencePiece (Llama, T5). Example: “unhappiness” → “un”, “happi”, “ness”.

Embeddings

  • An embedding is a vector such as [0.12, -0.53, …] with hundreds or thousands of numbers.
  • Classic example: vector(“king”) − vector(“man”) + vector(“woman”) ≈ vector(“queen”).
  • Static embeddings (word2vec, GloVe) give one vector per word. Contextual embeddings (BERT, modern embedding models) change with the sentence: “river bank” vs “bank loan”.
  • Uses: semantic search, RAG retrieval, clustering, classification, duplicate detection, recommendations.

Cosine similarity — the one formula to memorise

cos(A, B) = (A · B) / (‖A‖ × ‖B‖)

Ranges from −1 (opposite) through 0 (unrelated) to 1 (same direction). If vectors are normalised to length 1, cosine = dot product.

import numpy as np
def cosine(a, b):
    a, b = np.array(a), np.array(b)
    return float(a @ b / (np.linalg.norm(a) * np.linalg.norm(b)))
print(cosine([1, 0, 1], [1, 1, 1]))   # 0.816
Say it in the interview“An embedding maps text to a vector where distance reflects meaning. I embed documents once, store them, embed each query with the same model, and retrieve the nearest vectors by cosine similarity.”

4Transformers & attention

The transformer (paper: “Attention Is All You Need”, 2017) is the architecture behind every modern LLM. Its key idea, self-attention, lets every word look at every other word and decide which ones matter for its meaning.

Self-attention like a classroom

In “The animal didn’t cross the street because it was tired”, the word “it” needs to look back at “animal”. Each token makes three vectors:

  • Query (Q) — what I am looking for.
  • Key (K) — what I contain (a label others can match).
  • Value (V) — the information I hand over if chosen.

Attention(Q, K, V) = softmax( Q·Kᵀ / √dₖ ) · V

Q·Kᵀ scores how well each pair matches; dividing by √dₖ stops scores from growing too large (which would make softmax output almost all 0s and 1s and kill gradients); softmax turns scores into weights; the output is a weighted mix of values.

The rest of the block

  • Multi-head attention: several attention “views” in parallel — one may track grammar, another who-refers-to-whom.
  • Positional encoding: attention by itself ignores order, so position is added (sinusoidal, learned, or RoPE rotary — used by most modern LLMs).
  • Each layer: attention → add & layer-norm → feed-forward network → add & layer-norm. The “add” is a residual connection that keeps training stable in deep stacks.
  • Causal mask: in a generator, token 5 may not look at token 6 (the future).
FamilySeesGood atExamples
Encoder-onlyBoth directionsUnderstanding, classification, embeddingsBERT, RoBERTa
Decoder-onlyOnly the past (causal)Generating text — today’s chat LLMsGPT, Claude, Llama, Gemini, Mistral
Encoder-decoderEncoder both; decoder pastTranslation, summarisationT5, BART

Why transformers beat RNNs/LSTMs

RNNs read one word at a time, so training is slow and long-distance links fade. Transformers process all tokens in parallel on GPUs and connect any two tokens directly. The cost: attention is O(n²) in sequence length, which is why long context is expensive (fixes: FlashAttention, sliding-window attention, KV-cache tricks).

Mixture of Experts (MoE): a router sends each token to only a few “expert” feed-forward networks, so a model can have huge total parameters but use a small fraction per token (e.g. Mixtral, DeepSeek-V3).

Say it in the interview“Self-attention computes, for every token, a weighted average of all tokens’ values, where weights come from query–key similarity scaled by √dₖ. Multi-head lets it learn several relationships at once, positional encoding gives order, and the causal mask makes decoder-only models generate left to right.”

5How LLMs are trained

A chat model is built in stages: first it reads the internet to learn language (a super-autocomplete), then it is taught to follow instructions, then it is tuned to be helpful and safe.

  1. Pre-training — predict the next token over trillions of tokens. Result: a base model that continues text but doesn’t reliably follow instructions.
  2. Supervised fine-tuning (SFT) / instruction tuning — train on (prompt → ideal answer) pairs written or checked by people.
  3. Preference alignment — RLHF: people rank answers, a reward model learns their taste, then RL (PPO) pushes the model toward high-reward answers. DPO skips the separate reward model and learns directly from “chosen vs rejected” pairs. RLAIF / Constitutional AI uses AI feedback guided by written principles.
  4. Reasoning training — RL on checkable tasks (maths, code) teaches models to “think” step by step before answering; more thinking at answer time = test-time compute.

Key terms

  • Parameters: the learned weights (7B = 7 billion numbers).
  • Context window: the maximum tokens (input + output) the model handles in one call.
  • Knowledge cutoff: the model knows nothing after its training data ends — one reason for RAG and web search.
  • Scaling laws: quality improves predictably with more parameters, data and compute. Chinchilla finding: roughly 20 training tokens per parameter is compute-optimal.
  • Hallucination: fluent, confident, wrong output. Cause: the model predicts plausible text; it does not look facts up.
  • Open-weight (Llama, Mistral, Qwen, Gemma, DeepSeek) — you can host and fine-tune them; more control and privacy, more ops work. Closed API (GPT, Claude, Gemini) — strongest quality and zero hosting, but per-token cost and data leaves your servers.
Say it in the interview“Pre-training gives knowledge and language through next-token prediction; SFT teaches the assistant format; RLHF or DPO aligns it with human preferences. Hallucination comes from the objective itself — it optimises for plausible text, not verified truth — so in applications I ground answers with retrieval and evaluate faithfulness.”

6Inference, decoding & cost

At each step the model outputs a probability for every possible next token. Decoding settings decide how we pick from that list — safely and predictably, or creatively.

SettingWhat it doesUse
GreedyAlways pick the most likely tokenDeterministic, can be repetitive
TemperatureDivides the scores before softmax. Low → sharper, safer; high → flatter, more varied0–0.3 extraction, code, facts; 0.7–1 brainstorming
Top-kSample only from the k most likely tokensCuts off weird low-probability tokens
Top-p (nucleus)Sample from the smallest set whose probabilities add up to p (e.g. 0.9)Adapts to how confident the model is
Max tokens / stop sequencesHard limit on length / where to stopCost control, clean output
Beam searchKeep several candidate sequencesTranslation; rarely for chat

Speed and memory

  • KV cache: store each past token’s keys and values so the next token doesn’t recompute everything.
  • Latency = TTFT (time to first token) + output tokens ÷ tokens per second. Streaming makes it feel faster.
  • Quantization: store weights in fewer bits (16-bit → 8 or 4-bit). Less memory, faster, small quality loss. Formats: GGUF (llama.cpp/Ollama), GPTQ, AWQ.
  • Memory rule: parameters × bytes. 7B × 2 bytes (FP16) ≈ 14 GB; at 4-bit ≈ 3.5–4 GB. Plus the KV cache, which grows with context length.
  • Serving engines: vLLM (PagedAttention, continuous batching), TGI, TensorRT-LLM; locally Ollama / llama.cpp.
  • Speculative decoding: a small model drafts several tokens, the big model verifies them in one pass.

Cost

cost ≈ input tokens × input price + output tokens × output price

Output tokens usually cost several times more than input. Cut cost with shorter prompts, a smaller model for easy requests (routing), caching (prompt caching, semantic cache), batch APIs for offline jobs, and a sensible max_tokens.

Say it in the interview“For extraction I use temperature near zero and a JSON schema; for creative tasks higher temperature with top-p. To cut latency I stream, route simple queries to a small model, cache, and keep prompts short.”

7Prompt engineering

A prompt is a brief for a very capable new colleague who knows nothing about your situation. Be clear about the role, the task, the context, the rules and the exact output you want.

The six-part prompt

ROLE:     You are a support assistant for a health-insurance company.
TASK:     Answer the customer's question about their claim.
CONTEXT:  <policy> ...retrieved policy text... </policy>
RULES:    Use only the policy text. If it doesn't contain the answer, say
          "I don't know — please contact support." Never give medical advice.
FORMAT:   Reply in JSON: {"answer": str, "policy_section": str}
EXAMPLES: Q: Is dental covered? → {"answer": "...", "policy_section": "4.2"}
TechniquePlain meaning
Zero-shotJust ask, no examples
Few-shotShow 2–5 input → output examples so the model copies the pattern
Chain-of-thoughtAsk it to reason step by step before answering; helps maths and logic. Reasoning models do this internally.
Self-consistencySample several reasoning paths and take the majority answer
Prompt chainingSplit a big task into steps; output of one becomes input of the next
ReActReason, act with a tool, observe, repeat — the base of agents
Delimiters / XML tagsWrap data in tags like <doc> so the model can tell instructions from data
Structured outputAsk for JSON matching a schema (or use the API’s JSON/structured-output mode) and validate it

Prompt injection

Untrusted text tells the model “ignore your instructions and …”. Direct: typed by the user. Indirect: hidden in a web page, email or PDF the model reads. Defences (layers, none perfect): keep instructions separate from data, delimit untrusted text, give tools the least privilege, validate outputs, require human approval for risky actions, and monitor.

Say it in the interview“I treat prompts like code: versioned, tested against an evaluation set, and changed one variable at a time. I start zero-shot, add few-shot examples for format, and use structured outputs with validation for anything a program will parse.”

8Vector databases

A vector database stores embeddings with their text and metadata, and answers “which stored vectors are closest to this one?” very fast — even across millions of items.

  • Exact (flat) search compares the query with every vector: perfect but slow at scale.
  • ANN (approximate nearest neighbour) trades a little recall for big speed: HNSW (a layered graph you hop through — most popular), IVF (cluster first, search a few clusters), PQ (compress vectors to save memory).
  • Distance: cosine, dot product, Euclidean (L2). Normalised vectors → cosine = dot.
  • Metadata filters: “only documents for client X from 2025” — essential for permissions.
  • Golden rule: embed documents and queries with the same embedding model. Changing models means re-embedding everything.
OptionWhen to pick it
FAISSLibrary (not a server); fast experiments, in-memory
ChromaEasiest local start for prototypes
pgvectorYou already use PostgreSQL — vectors next to your normal data and SQL filters
Qdrant / Weaviate / MilvusOpen-source, production scale, hybrid search, filtering
PineconeFully managed, no ops
Elasticsearch / OpenSearchStrong keyword (BM25) plus vectors in one place

Embedding models: OpenAI text-embedding-3, Cohere Embed, Voyage, and open models like BGE, E5, GTE, all-MiniLM (sentence-transformers). Compare on the MTEB leaderboard, then test on your own data.

Say it in the interview“I choose by scale, ops appetite and existing stack: pgvector if we’re already on Postgres and under a few million vectors; Qdrant or a managed service for larger scale; and I make sure it supports metadata filtering and hybrid search.”

9RAG — retrieval-augmented generation

RAG is an open-book exam for the model: first find the relevant pages in your documents, then let the model answer using only those pages, with citations.

Why: private or fresh knowledge, fewer hallucinations, citations users can check, and updating knowledge = updating documents (no retraining).

Two pipelines

INDEXING (offline):  load → clean/parse (PDF, OCR) → chunk → embed → store (+ metadata)
QUERY (online):      question → (rewrite) → embed → retrieve top-k → (rerank)
                     → prompt with context → LLM answer with citations → (check)

Chunking

  • Fixed size with overlap (e.g. 300–800 tokens, 10–20% overlap) — simple baseline.
  • Recursive (split by headings → paragraphs → sentences), structure-aware (Markdown/HTML headings, tables kept whole), semantic (split where meaning changes).
  • Parent–child: retrieve small precise chunks, send their bigger parent section to the model.
  • Too small → loses context; too big → noisy and costly. Decide with an evaluation set, not by guess.

Better retrieval

  • Hybrid search = keyword BM25 (exact words, IDs, names like “NPI 1234”) + vector search (meaning). Merge with Reciprocal Rank Fusion (RRF).
  • Reranking: a cross-encoder reads (question, chunk) together and scores relevance — more accurate than embeddings; run on the top 20–50.
  • Query rewriting / multi-query; HyDE (write a hypothetical answer, embed that); contextual retrieval (prepend a one-line summary of the document to each chunk).
  • GraphRAG: build a knowledge graph of entities and relations for “connect-the-dots” questions. Agentic RAG: an agent decides when and where to search. Corrective RAG: grade retrieved chunks and fall back (e.g. web search) when they’re poor.

Why RAG fails, and how to debug (in this order)

  1. Retrieval first: is the right chunk in the top-k? Measure recall@k on a golden set.
  2. If not: parsing errors (tables, scanned PDFs), bad chunking, wrong embedding model, need hybrid search or reranking, missing metadata filters, stale index.
  3. If yes but the answer is wrong: prompt doesn’t enforce grounding, context too long (lost in the middle — models use the start and end of long context best), conflicting documents.
  4. Measure faithfulness (is every claim supported by the context?) and answer relevance.
PromptingRAGFine-tuningLong context
Adds knowledgeA littleYes, freshPoorly, goes staleYes, per call
Changes style/formatSomeNoYesSome

Say it in the interview“When a RAG answer is wrong I separate retrieval from generation. I check whether the right chunk was retrieved; if not I fix parsing, chunking, add hybrid search and a reranker. If it was retrieved, I tighten the grounding prompt and measure faithfulness on a golden set.”

10Agents, tool calling & MCP

An agent is an LLM in a loop: it decides the next step, uses a tool (search, database, calculator, email), looks at the result, and repeats until the goal is done.

Agent = LLM + tools + loop + memory + guardrails

Tool (function) calling

You describe each tool with a name, description and JSON schema. The model replies with “call tool X with these arguments”. Your code runs the tool, sends the result back, and the model continues.

tools = [{"name": "get_weather",
          "description": "Current weather for a city",
          "input_schema": {"type": "object",
                           "properties": {"city": {"type": "string"}},
                           "required": ["city"]}}]
resp = client.messages.create(model=MODEL, max_tokens=500, tools=tools,
           messages=[{"role": "user", "content": "Weather in Chennai?"}])
if resp.stop_reason == "tool_use":
    call = next(b for b in resp.content if b.type == "tool_use")
    result = get_weather(**call.input)            # YOUR code executes the tool
    # next request: append the assistant turn (resp.content) and a user turn with
    # {"type": "tool_result", "tool_use_id": call.id, "content": result}

Patterns — start with the simplest

  • Workflows (fixed path you code): prompt chaining, routing (classify then send to the right handler), parallelisation, orchestrator–workers, evaluator–optimiser (one model drafts, another critiques).
  • Agents (model chooses the path): use when steps can’t be predicted in advance. More flexible, less predictable, costlier.
  • ReAct: Thought → Action → Observation, repeated.
  • Memory: short-term = conversation in the context window; long-term = facts saved in a database / vector store and retrieved later; summarise old turns to save tokens.
  • Multi-agent: a supervisor hands sub-tasks to specialist agents. Frameworks: LangGraph, CrewAI, AutoGen, OpenAI Agents SDK, Claude Agent SDK, LlamaIndex.

MCP — Model Context Protocol

An open standard (introduced by Anthropic in Nov 2024, now widely adopted) for connecting AI apps to tools and data. Think “USB-C for AI”: build an MCP server once (it exposes tools, resources and prompts), and any MCP client (Claude apps, IDEs, agent frameworks) can use it.

# pip install "mcp[cli]"
from mcp.server.fastmcp import FastMCP
mcp = FastMCP("leave-policy")

@mcp.tool()
def leave_balance(employee_id: str) -> str:
    """Return remaining casual leaves for an employee."""
    return {"E001": "7 days"}.get(employee_id, "not found")

if __name__ == "__main__":
    mcp.run()
Agent risks: infinite loops (cap the steps), wrong arguments (validate), runaway cost (budgets), prompt injection through tool results, and irreversible actions (sending email, payments) → human-in-the-loop approval and least-privilege credentials.
Say it in the interview“I start with the simplest thing that works — a single call, then a fixed workflow — and only move to an autonomous agent when the steps can’t be predicted. Every agent gets a step limit, validated tool inputs, least-privilege access, tracing, and human approval for irreversible actions.”

11Fine-tuning (LoRA, QLoRA)

Fine-tuning continues training a model on your own examples so it behaves the way you want. It teaches behaviour, format and style well; it is a poor way to add facts that change.

The decision ladder

  1. Better prompt (cheapest, fastest to change).
  2. RAG — if the problem is missing knowledge.
  3. Fine-tune — if the problem is behaviour: consistent format, tone, domain jargon, a narrow task, or making a small, cheap model match a big one.
  4. Often the answer is RAG + a fine-tuned model together.

LoRA in one picture

Freeze the original weight matrix W. Learn two thin matrices A and B so the update is W′ = W + B·A with a small rank r (e.g. 8–64). You train well under 1% of the parameters; adapters are a few MB and can be swapped per task.

QLoRA = LoRA on a base model loaded in 4-bit. Lets you fine-tune a 7–8B model on a single free/cheap GPU (Colab, Kaggle).

Doing it well

  • Data > everything: a few hundred to a few thousand clean, consistent examples in chat-format JSONL; de-duplicate; keep a held-out test set.
  • Hyper-parameters: learning rate, 1–3 epochs, batch size, rank r, alpha. Watch validation loss for overfitting.
  • Catastrophic forgetting: narrow training can erase general skills — mix in general data, use LoRA, keep epochs low.
  • Tools: Hugging Face transformers, peft, trl (SFTTrainer, DPOTrainer), Unsloth (fast, free Colab notebooks), Axolotl; or a provider’s fine-tuning API.
  • Distillation: a big “teacher” model generates training data for a small “student”.
Say it in the interview“I fine-tune for behaviour, not for facts. My order is prompt, then RAG, then fine-tune — and I’d use LoRA or QLoRA so it fits on one GPU, evaluating against the base model on a held-out set before shipping.”

12Evaluation

You can’t improve what you don’t measure. Because LLM output varies, “it looked fine when I tried it” is not evidence. Build a test set and score every change against it.

The evaluation stack

  1. Golden dataset: 50–200 real or realistic inputs with expected answers or grading criteria, including hard and adversarial cases. Grow it from production failures.
  2. Code checks: valid JSON? required fields? length? forbidden words? exact match for short answers.
  3. Reference metrics: BLEU / ROUGE (word overlap — weak for open-ended answers), BERTScore / embedding similarity (meaning).
  4. LLM-as-a-judge: a model grades answers against a rubric (pointwise 1–5, or pairwise A vs B). Known biases: position, verbosity (prefers longer), self-preference. Mitigate: clear rubric, temperature 0, swap order, calibrate against human labels.
  5. Human review for high-stakes or subjective quality.
  6. Online: A/B tests, thumbs up/down, task success, escalation rate, cost and latency.
RAG metricPlain meaning
Recall@kDid the right chunk appear in the top k?
Precision@k / MRR / nDCGHow much of top k is relevant / how high the first good one ranks / ranking quality
Faithfulness (groundedness)Is every claim in the answer supported by retrieved context?
Answer relevanceDoes it actually answer the question?
Context precision / recallWas retrieved context focused / complete? (RAGAS names)

Public benchmarks (MMLU, GSM8K, HumanEval, SWE-bench, GPQA, Chatbot Arena) help you shortlist models — they don’t tell you how your app performs. Perplexity measures how “surprised” a language model is by text (lower = better); used for models, rarely for apps.

Tools: RAGAS, DeepEval, promptfoo, OpenAI Evals, LangSmith, Langfuse, Arize Phoenix.

Say it in the interview“I build a golden set from real queries, score it with code checks plus an LLM judge calibrated on human labels, split RAG scores into retrieval and generation, and run it as a regression test whenever a prompt, model or index changes.”

14Safety & responsible AI

Responsible AI means the system is accurate enough for its job, protects people’s data, treats people fairly, and can’t easily be tricked into doing harm.

  • Hallucination → ground in sources, cite, allow “I don’t know”, low temperature, a verification step, evaluate faithfulness.
  • Privacy → minimise and redact PII/PHI; know HIPAA (US health data), GDPR (EU), India’s DPDP Act 2023; check provider data-retention terms.
  • Security → OWASP Top 10 for LLM Applications: prompt injection, sensitive information disclosure, supply chain, data/model poisoning, improper output handling, excessive agency, system prompt leakage, vector/embedding weaknesses, misinformation, unbounded consumption.
  • Bias & fairness → test outputs across groups; avoid using models for high-stakes decisions about people without human review.
  • Guardrails → input/output classifiers, moderation APIs, Llama Guard, NeMo Guardrails, schema validation, allow-lists for tools.
  • Red-teaming → deliberately attack your own system (jailbreaks, injections, data extraction) before users do.
  • Governance → EU AI Act (risk tiers), NIST AI Risk Management Framework, model cards, audit logs, human oversight.
Say it in the interview“For a healthcare assistant I’d redact PHI before it reaches the model, enforce permission-aware retrieval, ground every answer in cited policy text, block medical advice with an output guardrail, keep a human in the loop for decisions, and red-team it against the OWASP LLM Top 10.”

Stable Diffusion works in a compressed latent space (cheaper than pixels) and uses classifier-free guidance to control how strongly the image follows the prompt.

Say it in the interview“Diffusion models learn to reverse a noising process. At generation time they start from random noise and denoise over many steps, conditioned on a text embedding — Stable Diffusion does this in a VAE latent space for efficiency.”

16System design & storytelling

Design rounds test structured thinking, not a perfect diagram. Walk the same ten steps every time and talk about trade-offs out loud.

The 10-step answer frame

  1. Clarify: users, use cases, scale (users/day, documents), latency target, data sensitivity, languages, success metric.
  2. Data: sources, formats (PDF, scans, tables), freshness, permissions.
  3. High-level architecture — draw boxes: ingestion → index → API → orchestrator → model → UI.
  4. Retrieval: chunking, embedding model, vector DB, hybrid + rerank, metadata filters.
  5. Model choice: API vs open-weight, size, routing between small and large.
  6. Prompting / tools / agents: only as much autonomy as needed.
  7. Evaluation: golden set offline, metrics online.
  8. Safety: PII, injection, guardrails, human review.
  9. Cost & latency: estimate tokens per request × requests per day; caching; streaming.
  10. Monitoring & iteration: tracing, feedback, drift; then name trade-offs and next steps.

Worked example: “Design a claims-support chatbot for a health insurer”

Clarify: members ask about coverage and claim status; 20k chats/day; answers in under 3 s to first token; PHI involved; English + Tamil. Ingest policy PDFs with layout-aware parsing, chunk by section, embed, store in pgvector with plan-type metadata. Claim status comes from a tool (API call with the member’s ID), not from RAG. Router: simple FAQs → small model; complex coverage questions → larger model with reranked context. Prompt enforces citations and “I don’t know”. Guardrails redact PHI in logs and block medical advice. Evaluate with 150 golden questions (recall@5, faithfulness, judge score) and online deflection rate + CSAT. Cache frequent FAQs. Escalate to a human agent on low confidence.

Measuring business success (AI product / PMO angle)

Tie quality to outcomes: task success or deflection rate, time saved per task, cost per resolved request, adoption and retention, CSAT, escalation rate, and safety incidents. Report them on one dashboard next to model metrics.

Telling your project story (STAR+)

Situation  The problem and who had it (one line)
Task       What you owned
Action     What you built: architecture, stack, the hardest bug and how you fixed it
Result     A number: accuracy 62% → 85%, response 9 s → 2 s, 4 hours saved per week
Learning   What you'd change next time
Say it in the interview“Before I design anything, let me clarify the users, scale, latency target, data sensitivity and how we’ll measure success.” — this first sentence alone sets you apart.
